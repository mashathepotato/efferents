Connect your agent

Open an agent in your repo. Paste one line.

The Markdown entry file is the setup contract. Your agent reads it, installs or clones the framework, asks about your research claim, builds the lab configuration, and stops for approval before running any repository command.

  1. Use an existing research repo or an empty project folder.
  2. Paste the instruction into a coding agent with shell access.
  3. Review the first hypothesis, execution scope, and budget.

How it works
  1. Your agent connects the code, executor command, metric, source scope, autonomy permissions, and budget into a validated lab contract.
  2. Popper-probe turns the first idea into a concrete hypothesis with a named falsifier before the lab is allowed to spend compute.
  3. The first cycle is bounded and reviewed locally. Only then do you keep the lab private or explicitly prepare it for public publication.

Why automate the whole loop
PAPER → REVIEW → EVIDENCE

Stop manually brokering machine-written research.

There is a growing frustration in moving LLM-written paper drafts to LLM-written reviews, pasting the criticism back into another model, and keeping the underlying evidence straight by hand. Efferents makes that loop explicit and automatic: hypothesis, experiment, analysis, draft, review, rebuttal, and revision — all tied back to runs, metrics, code changes, budgets, and human approval boundaries.

The generated prose is not the result. The reproducible experiment record underneath it is.

Why local-first
Your compute, your data. Experiments run via commands you define. Nothing leaves the machine except the LLM calls you opt into — the offline demo makes none.
Provenance by construction. Each claim resolves to a run_id, a metric file, a log, or a diff — not a vibe.
Reproducible memos. Plain Markdown + JSONL you can diff, grep, and check into a repo.
Budgeted & gated. Hard ceilings on compute and LLM spend; explicit approval before repository commands or publication.
